# Научные компетенции МГТУ «СТАНКИН» в контексте мировой науки

Статический сайт о научных компетенциях университета на фоне мировой науки. Он показывает, в каких направлениях у университета выраженная специализация, как цитируются его работы по сравнению со средним мировым уровнем и какое место он занимает среди организаций России и мира. Все показатели рассчитываются автоматически по открытой базе научных публикаций [OpenAlex](https://openalex.org) (лицензия CC0).

**Адрес после публикации:** https://peretyaginmstu-jpg.github.io/stankin-science/

> Предварительная версия: страницы закрыты от поисковых систем (`noindex`, `robots.txt`). Индексацию включает `SITE.noindex = false` в `config/site.mjs`.

## Что есть на сайте

| Раздел | Путь | Содержание |
|---|---|---|
| Обзор | `/` | Ключевые показатели, карта компетенций (специализация × цитируемость), карточки компетенций, динамика публикаций, источники публикаций, страны-партнёры |
| Компетенции | `/competencies/` | Сравнительная таблица компетенций и «карта направлений» по всем подобластям OpenAlex |
| Страница компетенции | `/competencies/<id>/` | Показатели относительно мира, динамика университета и мирового потока, ведущие страны и организации мира и России с местом университета, темы, самые цитируемые работы, мировые обзоры, страны соавторов |
| Мировые тренды | `/trends/` | Портфель компетенций (рост мирового потока × специализация), быстрорастущие темы мировой науки, «белые пятна», темы, где университет растёт быстрее мира |
| Сотрудничество | `/collaboration/` | Страны и организации-партнёры, доля публикаций с зарубежными соавторами по годам |
| Методика | `/method/` | Источник и период данных, формулы показателей, состав каждой компетенции, ограничения, данные для загрузки (JSON и CSV) |

Языки: русский (корень) и английский (`/en/`). Тёмная тема включается по настройке системы. Графики перерисовываются под ширину экрана, у каждого есть таблица данных; на узких экранах пузырьковые диаграммы нумеруют точки и выводят список названий.

## Как считаются показатели

- **Индекс специализации** — доля направления в публикациях университета, делённая на долю этого направления в мировом потоке за тот же период. 1 — как в среднем по миру.
- **FWCI** (Field-Weighted Citation Impact) — цитируемость, нормализованная по подобласти, году и типу публикации; мир = 1,00. Показатель направления — среднее по работам.
- **Топ-10 %** — доля работ, входящих в 10 % самых цитируемых в своей области и году; мир = 10 %.
- **Доля в мировом потоке**, **рост** (второе пятилетие к первому — у университета и в мире), **место в России и мире** по числу публикаций.

Окно анализа — десять последних полных лет (сейчас 2016–2025), учитываются статьи, обзоры и главы книг (в том числе сборники конференций). Подробности и ограничения — на странице «Методика».

**Компетенции** — 18 тематических групп из ≈4500 тем классификации OpenAlex. Правила отнесения тем (по области, подобласти и ключевым словам в названии темы) лежат в `content/competencies.mjs`. Каждая тема попадает не больше чем в одну компетенцию; компетенция показывается на сайте, если у университета в ней не меньше 15 публикаций.

## Как обновляются данные

Сайт собирается и публикуется в GitHub Actions (`.github/workflows/pages.yml`):

1. `tools/fetch-openalex.mjs` выгружает данные из OpenAlex API в снимок `data/snapshot/snapshot.json` — около 300–500 запросов, то есть 3–5 тыс. кредитов из 100 тыс., которые бесплатный ключ даёт на сутки;
2. `tools/build.mjs` рассчитывает показатели и собирает страницы в `dist/` (сеть не нужна);
3. `tools/check.mjs --publish` проверяет сборку и не пропускает демо-данные;
4. сборка публикуется на GitHub Pages, а снимок данных сохраняется в артефактах запуска на 90 дней.

Запуски: при каждом изменении `main`, по расписанию 3-го числа каждого месяца и вручную (Actions → «Публикация» → Run workflow; флажок `refresh` заставляет выгрузить данные заново). Снимок кэшируется на месяц, поэтому повторные сборки в том же месяце не тратят запросы.

### Что нужно сделать один раз

1. **Ключ OpenAlex.** С февраля 2026 года API OpenAlex требует ключ. Он бесплатный: зарегистрируйтесь на openalex.org и скопируйте ключ на странице https://openalex.org/settings/api. Добавьте его в репозиторий как секрет `OPENALEX_API_KEY`: Settings → Secrets and variables → Actions → New repository secret.
2. **GitHub Pages.** Settings → Pages → Source: **GitHub Actions**.
3. Запустите workflow «Публикация» вручную или отправьте любое изменение в `main`.

Пока ключа нет, workflow прогоняет тесты и завершается с предупреждением, ничего не публикуя.

## Локальная работа

Нужен Node.js 22 или новее. Зависимостей нет.

```bash
npm test                      # тесты: расчёты, графики, правила компетенций, сквозная выгрузка на имитации API
npm run demo                  # сборка из синтетических данных в dist-demo/ (на страницах — плашка «демо»)
node tools/serve.mjs --dir dist-demo   # просмотр: http://localhost:8080/stankin-science/
```

Сборка из настоящих данных:

```bash
OPENALEX_API_KEY=ваш_ключ node tools/fetch-openalex.mjs   # → data/snapshot/snapshot.json
node tools/build.mjs                                     # → dist/
node tools/check.mjs --dir dist --publish
node tools/serve.mjs
```

Если интернет доступен только через прокси, встроенный `fetch` в Node учитывает `HTTPS_PROXY` при `NODE_USE_ENV_PROXY=1` (Node 22.21 и новее).

Демо-снимок `data/fixture/snapshot.json` создаётся командой `npm run fixture` (`npm test` и `npm run demo` делают это сами). **Все числа, организации и публикации в нём выдуманы**: он нужен только для разработки и тестов, а публикацию такой сборки блокирует `tools/check.mjs --publish`.

## Как менять содержимое

| Что | Где |
|---|---|
| Состав компетенций, их названия и описания | `content/competencies.mjs` |
| Тексты страниц и подписи интерфейса (ru/en) | `content/i18n.mjs` |
| Русские названия областей и подобластей OpenAlex | `content/taxonomy.mjs` |
| Организация, окно анализа, типы публикаций, пороги, запрет индексации | `config/site.mjs` |

После выгрузки сборка печатает в журнал, сколько работ попало в каждую компетенцию и какие темы университета остались вне компетенций, — по этому списку удобно уточнять правила. Изменение правил компетенций меняет и мировой контекст (страны и организации), поэтому после правки нужна новая выгрузка; сборка из старого снимка скроет устаревший контекст и предупредит об этом на странице компетенции.

Если в OpenAlex найдутся дубли записи университета, журнал выгрузки и страница «Методика» их покажут; идентификаторы дублей добавляются в `INSTITUTION.extraIds`.

## Структура репозитория

```
config/site.mjs              настройки: организация (ROR, OpenAlex ID), период, пороги, адреса
content/                     компетенции, тексты ru/en, русские названия классификации
src/lib/                     клиент OpenAlex, отнесение тем к компетенциям, расчёт показателей,
                             форматирование чисел и типографика
src/charts/charts.mjs        SVG-графики (работают и при сборке, и в браузере)
src/render/                  шаблоны страниц
src/assets/                  стили, скрипт страниц, шрифты, логотип
tools/fetch-openalex.mjs     выгрузка данных
tools/build.mjs              сборка сайта
tools/check.mjs              проверки сборки
tools/serve.mjs              локальный просмотр
tools/make-fixture.mjs       синтетический снимок для разработки
test/                        тесты (node --test) и имитация OpenAlex API
.github/workflows/           check.yml — тесты и демо-сборка; pages.yml — выгрузка, сборка, публикация
```

## Безопасность и доступность

- Страницы статические, с Content-Security-Policy: скрипты, стили, шрифты и изображения загружаются только с самого сайта, встроенных скриптов и стилей нет.
- Подписи из данных OpenAlex экранируются при сборке и выводятся в подсказках через `textContent`.
- Цвета графиков проверены на различимость при нарушениях цветового зрения в светлой и тёмной теме; значения доступны в таблицах, подсказки открываются и с клавиатуры.
