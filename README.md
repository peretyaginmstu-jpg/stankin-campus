# Новый кампус МГТУ «СТАНКИН»

Сайт о новом кампусе МГТУ «СТАНКИН» в Коммунарке: учебный комплекс из семи корпусов, Головной центр компетенций (ГЦК), общежития, спортивный центр, общественные пространства и ход строительства.

**Адрес:** https://peretyaginmstu-jpg.github.io/stankin-campus/

> Это предварительная версия для согласования, доступ по приглашению. Содержимое страниц зашифровано и открывается только после входа по логину и паролю. Поисковым системам индексация запрещена (`robots.txt`, `noindex`).

## Как устроена защита

Сайт статический и размещается на GitHub Pages, поэтому доступ ограничен шифрованием на стороне браузера, а не сервером.

1. Каждая HTML-страница содержит только экран входа и зашифрованный блок `<script id="gate-data">` с самой страницей.
2. Из логина (без учёта регистра) и пароля через PBKDF2-SHA-256 (250 000 итераций, общая соль) получается ключ AES-GCM-256.
3. Этим ключом браузер расшифровывает страницу и показывает её. Если логин или пароль неверны, расшифровка не проходит.
4. Ключ сохраняется в `localStorage` (`gate.key`) на 7 дней, чтобы не вводить пароль на каждой странице. Если соль сменилась (сайт перешифрован с новыми данными для входа), сохранённый ключ перестаёт действовать.
5. Данные каталога объектов (`campus-data*.enc.json`) зашифрованы тем же ключом и расшифровываются в `app.js`.

Для работы нужен JavaScript и браузер с поддержкой Web Crypto API (любой современный браузер; сайт должен открываться по HTTPS).

## Структура репозитория

В репозитории лежит **готовая сборка** сайта: файлы публикуются как есть, без шага сборки на стороне GitHub.

```
index.html, 404.html          главная и страница «не найдено» (ru)
campus/ science/ life/        разделы на русском
partners/ project/ sources/
en/ zh/                       те же страницы на английском и китайском
campus-data*.enc.json         зашифрованные данные каталога объектов (ru / en / zh)

styles.css                    базовые стили и шрифты
ui.css, ui.js                 общий слой: шапка, появление блоков, счётчики, анимации
home.css                      стили главной страницы
interior.css                  стили внутренних страниц
a11y.css, a11y.js             версия для слабовидящих
app.js                        меню, просмотр изображений, каталог объектов, фильтры хроники
i18n.js                       подписи интерфейса на трёх языках

assets/                       изображения (webp, варианты -900 и -1600), видео, логотипы
assets/fonts/                 шрифты Golos Text и Prata (woff2 по наборам символов)
assets/icons/                 иконки Lucide
.nojekyll                     отключает обработку Jekyll на GitHub Pages

tools/check.mjs               проверки сборки (см. «Проверки»)
.github/workflows/check.yml   запуск проверок в GitHub Actions
.gitignore, .editorconfig     служебные файлы
```

Исходники страниц и скрипты сборки (`scripts/build.py`, `scripts/validate.py`), которые упоминаются в комментариях к коду, в этом репозитории не хранятся. Правки текста и содержимого страниц нужно делать в исходниках, заново собирать и шифровать сайт, а затем публиковать результат сюда. HTML-файлы в этом репозитории вручную не редактируются: их содержимое зашифровано.

Все пути в HTML начинаются с `/stankin-campus/`. Скрипты вычисляют адреса ресурсов от своего расположения, но в разметке префикс задан явно, поэтому при переносе на другой адрес сайт нужно пересобрать.

## Локальный просмотр

Сборка рассчитана на размещение в подпапке `/stankin-campus/`, поэтому для локального просмотра её нужно отдавать с тем же префиксом:

```bash
mkdir -p /tmp/site && ln -s "$PWD" /tmp/site/stankin-campus
python3 -m http.server 8000 --directory /tmp/site
```

Откройте http://localhost:8000/stankin-campus/ и войдите с выданными логином и паролем. Адрес `localhost` считается безопасным, поэтому Web Crypto работает и без HTTPS.

## Проверки

```bash
node tools/check.mjs
```

Зависимостей нет; проверено на Node 22 (на более старых версиях не запускалось). Тот же скрипт запускается в GitHub Actions (`.github/workflows/check.yml`) на каждый push и pull request, а также вручную. Он проверяет:

- синтаксис `app.js`, `ui.js`, `a11y.js`, `i18n.js`;
- переводы: у `ru`, `en`, `zh` одинаковые наборы ключей в `i18n.js`, а каждый `T.<ключ>` из скриптов определён во всех языках;
- страницы: у каждой есть зашифрованный блок `gate-data`, в открытой части нет разметки страницы (`<nav`, `<footer`, `<figure`, `<h2`) и есть `noindex`, английская и китайская версии повторяют набор страниц русской, есть файлы данных каталога для всех языков;
- **одинаковые соль и число итераций у всех страниц и файлов данных**: если публикация смешала две сборки, сохранённый ключ подойдёт лишь к части файлов;
- ссылки на файлы (`/stankin-campus/...`, `url(...)` в CSS, буквальные `asset('...')` в JS) указывают на существующие файлы;
- предупреждения о размере: файл (кроме видео) тяжелее 1,5 МБ, страница-шлюз тяжелее 150 КБ.

Проверить можно только открытую часть: содержимое страниц и данные каталога зашифрованы, поэтому ссылки внутри них скрипт не видит.

## Публикация

Сайт публикуется на GitHub Pages из ветки `main`. Чтобы обновить сайт, достаточно закоммитить новую сборку и отправить её в `main`.

- В Settings → Pages → Source выбрано **GitHub Actions**: публикует workflow `Pages` (`.github/workflows/pages.yml`). Он сначала прогоняет `tools/check.mjs`, и сломанная сборка не публикуется. Перезапустить публикацию вручную: Actions → Pages → Run workflow.
- Если там выбрано **Deploy from a branch** (`main`, `/ (root)`), публикует встроенная сборка Pages, а workflow `Pages` только прогоняет проверки и пропускает деплой.

Если новая сборка копируется в репозиторий с заменой всего содержимого, файлы `tools/`, `.github/`, `.gitignore`, `.editorconfig` и правки открытых скриптов и стилей (`app.js`, `ui.js`, `a11y.js`, `i18n.js`, `*.css`) пропадут. Их нужно перенести в исходный проект, откуда собирается сайт.

## Известные ограничения и задачи для сборки

Это не исправлено, потому что зависит от исходного проекта и скриптов сборки, которых в этом репозитории нет. Часть пунктов — решения владельца сайта, а не ошибки.

**Что не защищено.** Шифруются только HTML-страницы и данные каталога. Изображения, видео, скрипты, стили и `og-image.jpg` лежат открыто, и при публичном репозитории видны любому. Если приватность снимков важна, их нужно шифровать или отдавать с сервера с настоящей авторизацией.

**Пароль.**
- У всех один общий логин и пароль, отозвать доступ одному человеку нельзя.
- В репозитории и его истории лежат 16 шифрований, и подбор пароля можно вести офлайн. Стойкость целиком зависит от длины пароля.
- PBKDF2 сейчас 250 000 итераций (`"it"` в каждом файле); действующая рекомендация OWASP для PBKDF2-HMAC-SHA256 — 600 000.

**Соль.** В истории 16 публикаций, и у каждой своя соль. Пользователи, зашедшие раньше, при следующей публикации выходят из системы (ключ в `localStorage` привязан к соли). Плюс, пока кэш GitHub Pages живёт до 10 минут, страница со старой солью может получить данные с новой и показать «Не удалось загрузить объекты». Если смена соли не нужна для отзыва доступа, её стоит держать постоянной.

**Экран входа.**
- Нет переключателя языка: выбрать `en` или `zh` до входа нельзя.
- GitHub Pages отдаёт только корневой `404.html`, поэтому `en/404.html` и `zh/404.html` недостижимы: англо- и китайскоязычный пользователь видит русскую страницу.
- Ключ AES хранится в `localStorage` в извлекаемом виде, кнопки «выйти» нет.
- Нет `<meta name="referrer">` и Content-Security-Policy.

**Скорость.** Страница шифруется без предварительного сжатия (base64 не сжимается), и в открытой части шлюза нет `preload`/`modulepreload` для стилей, шрифтов и скриптов.

**Вес репозитория.** Видео занимают около 34 МБ, `.git` весит около 57 МБ. Стоит вынести видео из git (Git LFS или внешний хостинг). В `assets/` есть файлы, на которые нет ссылок в открытых частях: `courtyard.jpg`, `stankin-logo-color.png`, `hero-aerial-2400.webp`, `fonts/*.ttf`. Не удаляйте их, не сверившись с исходниками: ссылки на них могут быть внутри зашифрованных страниц и данных.
